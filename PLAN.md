# Поиск 10 сетапов для автотрейда на данных TRADER.PRO

Рабочий план и договорённости. Файл нужен, чтобы новая сессия Claude Code
продолжила работу с того же места. Вместе с ним читать **INSIGHTS.md** (выводы, открытия,
решения пользователя, методика) и **HYPOTHESES.md** (реестр всех рассмотренных гипотез со
статусом — чтобы не повторяться). Оба файла дописывать сразу по ходу работы.

## Задача

1. Придумать и проверить на истории 10 сетапов для автотрейда фьючерсов
   Binance: каскады ликвидаций и принудительные продажи, следование за
   крупным игроком, зоны набора и раздачи, перекос толпы (фандинг, long/short),
   OI, CVD. Классические индикаторы допускаются, если дают преимущество.
2. Для каждого сетапа, который торгует в плюс, перебрать 100–200 комбинаций
   параметров: SL, TP или TP1-2-3 с частичным закрытием, перенос стопа в
   безубыток после TP1, трейлинг, выход по времени.
3. Итог: 10 сетапов, у каждого логика и 5 лучших наборов параметров.
   Итоговая страница с таблицами и кривыми капитала, код в репозитории.

## Договорённости

| Параметр | Значение |
|---|---|
| Биржа | Binance USDT-M Futures (`binancef`) |
| Монеты | Топ-100 по объёму; расширено до 400. Каждая гипотеза проверяется по когортам 1–50, 51–100, 101–200, 201–300, 301–400 (своя геометрия, свои издержки) |
| Стиль | Интрадей и свинг, таймфреймы 5m / 15m / 1h |
| Направления | Лонги и шорты, лонги в отчёте отдельно (приоритет пользователя) |
| Позиция | Номинал $100, маржа $20, плечо 5, проверка ликвидации до стопа (для исследования; в итоге — размер от риска на сделку) |
| Депозит и цель (решение пользователя 2026-09-30) | Депозит $3–5 тыс. на одну гипотезу (сетап), цель 5–10 % в месяц в идеале. Итоговые метрики считать в % от депозита при риске на сделку (0.5–1 %), с одновременными позициями и максимальной просадкой; сетап интересен, если при разумном риске даёт 5–10 % в месяц |
| Одновременные сделки | Без общего лимита; по одной монете в одном сетапе одна позиция |
| Комиссии | Мейкер 0.018%, тейкер 0.045% (VIP0 со скидкой BNB 10%); лимитные входы и TP по мейкеру, стопы и рыночные входы по тейкеру плюс проскальзывание |
| Критерий отбора | Чистая прибыль на отложенном периоде при PF > 1.3, не меньше 50 сделок, просадка не больше трети прибыли |
| Защита от подгонки | Оптимизация на ранней части истории, проверка на последних месяцах, которых оптимизация не видела; устойчивость на нескольких монетах |
| Контроль (решение пользователя) | Сделки сетапа сравниваются со случайными: та же минута в другой монете, та же монета в другой момент, случайное направление; сетап засчитывается, если на отложенном периоде обыгрывает подмену монеты и момента с p ≤ 0.10. Плюс вход без выходов (доходность через 1/4/12/24 бара) и вся процедура отбора на шуме (сколько «прибыли» находит отбор на случайных сигналах) |

## Глубина истории TRADER.PRO (тариф Pro, проверено 2026-09-30)

| Данные | Доступно с | Примерно |
|---|---|---|
| Свечи 1h / 1d (с taker buy volume, отсюда CVD) | 2025-10-02 | 12 мес |
| Свечи 5m | около 2026-04-11 | 5.5 мес |
| Фандинг | 2025-10-02 | 12 мес |
| Open interest 1h | около 2026-03-23 | 6 мес |
| Open interest 5m | около 2026-04-11 | 5.5 мес |
| Long/short ratio | 2026-04-11 | 5.5 мес |
| Ликвидации (bars) | 2026-06-06 | 4 мес |
| Стены в стакане (whale) | последние 30 дней, только 15 монет | 1 мес |

Следствие: сетапы на ликвидациях проверяются на 4 месяцах (3 на оптимизацию,
1 на проверку), на OI и long/short на 5.5–6 месяцах. Сетапы на стенах стакана
на истории не проверить: только как фильтр или для форвард-теста. Такие
сетапы помечаются в отчёте как проверенные слабо.

## Доступ к данным

- MCP-коннектор `trader-pro` работает (тариф Pro, 600 запросов в минуту). Для массовой выгрузки не
  годится: не больше 500 баров за вызов, и все данные идут через контекст.
- REST из контейнера: `https://trader-pro.org/data/v1`, заголовок
  `X-TP-API-Key`, ключ в переменной окружения `TRADERPRO_API_KEY`.
  Домен trader-pro.org из контейнера открыт (проверено 2026-09-30).
- Новый ключ в `TRADERPRO_API_KEY` принят (проверено 2026-09-30): тариф Pro,
  600 запросов в минуту, история 365 дней.
- Выгрузка в приоритете над сервером пользователя (решение пользователя):
  по умолчанию 580 запросов в минуту и 10 потоков.
- Формат `/instruments`: `{"count", "exchanges": {"binancef": [{"symbol",
  "status", "has_data", ...}]}}`. Остальные ответы совпали с документацией.
- Публичные API Binance и Bybit закрыты сетевой политикой, да и не нужны:
  работаем только на данных TRADER.PRO (решение пользователя).
- Массовые тикеры (`/tickers`) доступны с тарифа Business, поэтому топ-100
  считается так: каталог `/instruments?exchange=binancef`, затем оборот за
  30 дней по дневным свечам каждой пары.
- Документация API: https://trader-pro.org/ru/api-docs. Гайд платформы грузится
  из https://trader-pro.org/guide/content.ru.json (оттуда взяты идеи сетапов).

## Код (`tp/`)

| Файл | Что делает |
|---|---|
| `tp/api.py` | REST-клиент: лимит 580 запросов в минуту, повторы на 429/5xx, выгрузка окнами с дозапросом обрезанных краёв |
| `tp/fetch.py` | `python -m tp.fetch account`, `universe`, `all` — выгрузка в `data/raw/<набор>/<SYMBOL>.parquet`, дописывает хвост |
| `tp/data.py` | Сборка монеты в одну таблицу на 5m / 15m / 1h / 4h: свечи, дельта, OI, фандинг, long/short, ликвидации; всё по моменту доступности |
| `tp/engine.py` | Бэктест (numba): вход задаёт сигнал — рынок, лимитка по своей цене, стоп-ордер на пробой, ожидание N баров, срок жизни ордера (или рынок/лимитка -X ATR из сетки), стоп по ATR или структурный, TP1-2-3 с долями, безубыток, трейлинг, выход по времени, комиссии, проскальзывание, фандинг, проверка ликвидации, одна позиция на монету |
| `tp/features.py` | ATR, RSI, MFI, ADX, Боллинджер, z-score, всплески, старший ТФ, свипы свинг-уровней |
| `tp/setups.py` | 11 кандидатов, у каждого 3 варианта сигнала |
| `tp/research.py` | Сетка выходов (60 на вариант, итого 180 на сетап), разбивка на оптимизацию и отложенный период, отбор 5 лучших, отдельно по лонгам; пишет `results/` |
| `tp/hyp/` | 100 гипотетических сетапов (`b01.py` … `b10.py`), общие помощники (`common.py`: `ref` — BTC/ETH на той же сетке), проверка `python -m tp.hyp.check bNN`: ошибки, заглядывание вперёд (сигналы на обрезанной истории = на полной), сторона стопа и цены входа, плотность сигналов, минимум 40 сигналов на вариант |
| `tp/screen.py` | Первичный отбор без выбора геометрии: карта 630 простых геометрий по пути цены после сигнала против подмен (`python -m tp.screen --pool all`) |
| `tp/trader.py` | Супертрейдер: обезличенные снимки сигналов, оценка решений трейдера против базы |
| `.claude/agents/` | Субагенты проекта: `supertrader` (дискреционный трейдер), `inventor` (ТРИЗ/АРИЗ) |
| `tp/placebo.py` | Контрольные проверки: подмена монеты (тот же момент), момента (та же монета, сдвиг серии по кругу), направления; доходность входа без сетки выходов; вся процедура отбора на шуме |
| `tests/` | 21 тест движка (включая входы лимиткой, стоп-ордером, с ожиданием) и прогон всей цепочки на синтетике |

Проверено: на случайном блуждании (16 монет) все сетапы теряют примерно на
величину комиссий, ни одна комбинация не проходит отбор. Заглядывания вперёд нет.

Формат ответов проверен на живом ключе (BTCUSDT, все 8 наборов). Фандинг:
метки выплат округляются до минуты, `fund_last` держится до следующей выплаты.
Из топ-100 исключены стейблкоины и токенизированное золото (PAXG, XAUT).

## Как продолжить

Новая сессия на вебе: хук `.claude/hooks/session-start.sh` сам ставит зависимости и выводит
`python -m tp.status` (что есть, чего нет, открытые пункты плана). Если данных нет — команды ниже.

```bash
pip install -r requirements.txt
python -m pytest -q tests
python -m tp.fetch account            # ключ принят?
python -m tp.fetch universe           # data/universe.json
python -m tp.fetch all                # около 14 тыс. запросов, около получаса при 580 в минуту
python -m tp.research                 # results/*.json
```

## Непрерывная работа

Раз в час сессия сама себе присылает плановую проверку (send_later, пересоздаётся каждый раз):
`tp.status`, свести завершившееся в файлы знаний, закоммитить, запустить следующий шаг по плану,
обновить MORNING.md. Это держит сессию активной, чтобы контейнер с данными не освобождался. Полной
гарантии нет (сессию могут завершить) — тогда данные выкачиваются заново командами из «Как продолжить».

(`python -m tp.hyp.check`) → первичный отбор без выбора геометрии с подменами (`tp.screen`, по
когортам) → полный перебор выходов с контролем (`tp.research`) → оценка с поправкой на рынок и по
режимам → итог. Все направления ниже только поставляют в неё гипотезы или правят её.
Проверка, что ничего не забыто: `python -m tp.status`.
